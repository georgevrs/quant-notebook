Kalman Filters & Regime Models

Every model earlier in this unit has quietly assumed its parameters hold still. Real hedge ratios drift and jump; real markets switch between a small number of distinct worlds. This closing session gives you two tools built for exactly that: a filter that updates a running estimate as each new price arrives, and a model that assigns each day to one of a few hidden regimes. The core move: stop re-estimating from scratch and start updating a belief.

5.7.1 A hidden state, seen only through noise

Two sessions back you built models that assume a fixed relationship. This one drops that assumption on purpose.

Session 5.4 — Stationarity & ARMA Models fit one ARMA model to a return series and used it throughout — the coefficients were treated as fixed, unknown constants to be estimated once. Session 5.6 — Cointegration & Mean Reversion extended that idea to a pair of prices: if they are cointegrated, a fixed hedge ratio combines them into a spread that mean-reverts. Both are honest simplifications, and both can quietly stop being true. A merger changes what a stock's beta means overnight; an ETF's index reweighting changes a hedge ratio it took months to estimate; a market's whole character can shift from calm to panicked and back. This session is about parameters that move.

The trick that handles all of these is the same trick, wearing two costumes. A state-space model splits a system into two layers: a hidden state that evolves on its own, mostly out of sight, and a stream of observations that are all you ever get to see of it. When the hidden state is a continuous number that drifts a little each period — a hedge ratio, say — the standard tool is the Kalman filter (§5.7.2–§5.7.5). When the hidden state instead jumps between a small number of discrete labels — calm versus crisis — the standard tool is a hidden Markov model (§5.7.6–§5.7.7). Same skeleton, different kind of state.

📌 Key idea — two layers, one skeleton

Every model in this session has the same shape: something true you cannot see, moving a little (or jumping) between periods, and a noisy reading of it that is all the data gives you. The whole session is one question asked twice — continuous state (§5.7.2) or discrete state (§5.7.6) — with the same underlying logic both times: combine what you believed with what you just saw, weighted by how much you trust each.

5.7.2 How the Kalman filter works

The Kalman filter is Bayesian updating running on a schedule: predict, look, weigh the surprise, update.

The Kalman filter is the recursive recipe for tracking a continuous hidden state when the state evolves linearly and every noise term is Gaussian. Concretely, for a time-varying hedge ratio βt\beta_t linking two legs' daily returns xtx_t and yty_t: the state takes a small random step each day, βt=βt−1+ηt\beta_t = \beta_{t-1} + \eta_t, and you observe it only through a noisy regression, yt=xtβt+εty_t = x_t \beta_t + \varepsilon_t. Nothing here is specific to hedge ratios — the same recursion tracks any slowly-moving regression coefficient.

There is also a purely engineering reason to prefer this over the obvious alternative of "just re-fit OLS on everything so far". An expanding-window OLS needs to revisit every observation you have ever collected each time it is asked for an answer — memory and compute both grow with history. The filter needs exactly two numbers, βˆ\hat\beta and PP, no matter whether it is on day 10 or day 10,000: it is a streaming algorithm in the same sense a running mean or an EWMA is, and for the same reason — you update a small summary and throw the raw observation away. That is what lets a Kalman filter sit inside a live trading system re-quoting a hedge ratio on every tick, where re-running a regression from scratch would not keep up.

Each day the filter does the same four things, in the same order, and never needs to remember anything from before yesterday — the whole history of the pair is compressed into two numbers, the current estimate βˆ\hat\beta and its variance PP. That is what makes it cheap enough to run on every tick: this is Bayesian updating with the previous posterior serving as today's prior, exactly the machinery Session 5.3 — Bayesian Thinking: Priors, Shrinkage & Updating built for shrinkage estimators — applied here to a moving target instead of a fixed one.

Notice the shape: new belief = old belief + gain × surprise. That is the entire idea behind every adaptive estimator in this course, from the EWMA volatility forecasts you may meet later to the online learners of Session 12.4 — Gradient Boosting for Cross-Sectional Alpha — only the definition of "gain" changes.

5.7.3 The math of the Kalman filter

Two equations describe the world; four more describe how to learn from it. All of it falls out of one idea: minimise the variance of the updated estimate.

The model is a pair of linear-Gaussian equations — a state equation for how the truth moves, and an observation equation for what you see:

βt=βt−1+ηt,ηt∼N(0,q),yt=xtβt+εt,εt∼N(0,σε2)\beta_t = \beta_{t-1} + \eta_t, \quad \eta_t \sim N(0, q), \qquad y_t = x_t \beta_t + \varepsilon_t, \quad \varepsilon_t \sim N(0, \sigma_\varepsilon^2)

Given a prior belief βˆt−1|t−1\hat\beta_{t-1\mid t-1} with variance Pt−1|t−1P_{t-1\mid t-1}, the predict step just adds the process-noise variance qq to that variance: the estimate itself does not move (a random walk's best forecast of tomorrow is today), but the uncertainty grows. The update step is the one worth deriving in words: among every linear rule of the form new estimate == prediction +Ktet+\, K_t e_t, the value of KtK_t that minimises the variance of the new estimate is exactly the Kalman gain of §5.7.2's table — the ratio of "how uncertain was I" to "how uncertain am I about this observation, all in". That is the whole derivation: least-squares projection under uncertainty, repeated once per period.

Everything above specialises the general Kalman filter — a state vector, a transition matrix, an observation matrix — to a single scalar coefficient with no drift and no covariates beyond xtx_t. The scalar case is the one worth memorising by hand, because the multi-dimensional version resurfaces anywhere a system tracks several hidden quantities at once from noisy readings — a yield curve's level, slope and curvature factors in Session 11.2 — Duration, Convexity & Curve PCA, for instance, or a robot's position and velocity in the textbook engineering example. The predict/update logic does not change; only the algebra of the noise terms grows from scalars to matrices.

🧭 Margin note — two limits worth knowing by heart

Send σε2→∞\sigma_\varepsilon^2 \to \infty (the observation is pure noise) and Kt→0K_t \to 0: the filter ignores today entirely and keeps yesterday's estimate. Send q→0q \to 0 (the state never truly moves) and the filter turns into the recursive form of ordinary least squares on all the data so far — proven directly in the lab, and used as the sanity check before anything else is trusted (§5.7.4).

5.7.4 Dynamic hedge ratios, in code

A hedge ratio that is updated every day, rather than re-fit from a fixed window, is worth a name of its own.

Call the output of this recursion a dynamic hedge ratio: a hedge ratio produced by a filter that updates on every new observation instead of being re-estimated from scratch on a fixed historical window. Before trusting the filter on anything realistic, the lab checks the limit from §5.7.3's margin note: with q=0q = 0 and a diffuse starting variance, the filtered estimate must equal plain ordinary least squares (OLS) through the origin. It does, to six decimal places (0.807758 from the filter versus 0.807758 from np.linalg.lstsq) — the filter is not a different idea from OLS, only a more general one.

# y = x * beta + eps, beta_t = beta_{t-1} + eta_t
def kalman_beta(x, y, q, sigma_eps2, beta0=0.0, p0=1.0):
    beta_pred, p_pred = beta0, p0
    for t in range(len(x)):
        e = y[t] - x[t] * beta_pred            # innovation
        f = x[t] ** 2 * p_pred + sigma_eps2      # innovation variance
        k = p_pred * x[t] / f                   # Kalman gain
        beta_pred = beta_pred + k * e            # update
        p_pred = (1 - k * x[t]) * p_pred
        p_pred = p_pred + q                      # predict the next step

The real test is a hedge ratio that actually shifts. The lab simulates 1,500 days of two legs whose true ratio wanders gently (an ordinary day-to-day process-noise wobble) and then, at year 3.0, takes one deliberate, much larger jump — from 0.80 to about 1.63. `q` is chosen honestly: maximise the one-step-ahead likelihood using only the data before the jump (§5.7.5 explains why the jump itself must stay out of that calculation). Over the first 60 days after the break, the tuned Kalman filter's tracking error is lower than a 60-day rolling-OLS hedge ratio's: RMSE 0.418 against 0.444 (fig 5.7.3). Before the jump, with nothing unusual to react to, the two are indistinguishable — 0.025 versus 0.025 — which is exactly what you want: no penalty for being adaptive when nothing needs adapting to.

One path, however good, is not evidence — Session 5.2 — Regression & Inference That Doesn't Lie exists for a reason. The lab re-draws the noise 300 times, keeping the same jump and the same tuned qq, and computes the average gap between the two methods' post-break RMSE: 0.044, a standard error of 0.0008 away from zero, or 52 standard errors — not a lucky seed.

5.7.5 Where people go wrong: tuning the filter

The Kalman filter has exactly one knob, and it is tempting to turn it by looking at the answer.

The pitfall is not "pick the wrong number" — it is picking qq by fitting the very jump you are being graded on. Maximise the likelihood over data that includes the break, and you will find whatever qq makes that one jump look inevitable — a filter tuned to catch a break it has already seen, which is Session 6.1 — What a Backtest Is (and Isn't)'s look-ahead bias wearing a different hat. §5.7.4's qq was chosen on the pre-break segment alone for exactly this reason.

⚠️ Pitfall — "a bigger q is just more responsive, so why not use one?"

Because responsiveness to a real break and sensitivity to ordinary noise are the same knob. The table above is one simulated path, but the direction is not a matter of luck — it is a property of the Kalman recursion itself (a bigger qq mechanically raises the gain every single day, break or not), which is why the lab asserts it directly rather than across replicates. Choosing qq is a bet on how often genuine breaks happen; choose it from history that only shows ordinary days, and you are betting breaks are rarer than they are.

There is a second, quieter assumption worth naming: this whole session has treated qq as one fixed number for the entire series. A hedge ratio in a calm market and the same hedge ratio during a liquidity crunch are unlikely to wander at the same rate — the process noise itself may depend on which of §5.7.6's regimes you are in. A single, permanently well-tuned qq is a compromise between "too jumpy in calm times" and "too sluggish in turbulent ones", not a solution to both at once. A regime-dependent qq is a natural next step for anyone who finishes this session wanting more, and it is exactly the kind of extension that becomes easy once §5.7.6's second tool is in your hands.

5.7.6 Hidden Markov models: when the state is discrete

Sometimes the hidden state isn't a wandering number — it's one of a few distinct worlds, and the interesting question is which one you're in today.

A hidden Markov model (HMM) is a state-space model whose hidden state is not a continuous number but one of a handful of discrete labels, each with a fixed probability of persisting or switching to another. Each of those labels is a market regime — a persistent, recurring set of statistical conditions the market can return to more than once. Calm and crisis are the classic pair: similar in spirit to Session 5.1 — Stylized Facts of Returns's volatility clustering and leverage effect, but now made explicit as two separate worlds with their own mean and volatility, rather than one process whose volatility happens to move around.

This is a good moment to separate two ideas this session has used side by side. §5.7.4's hedge-ratio jump was a structural break: a permanent change in the relationship itself, after which the old value never returns — the merger that permanently changes a beta, the index reweighting that permanently changes a hedge ratio. A regime is the opposite kind of change: calm returns after crisis ends, with the same calm-regime statistics as before. Reach for a Kalman filter (or a break test such as Bai & Perron's, in Go deeper) when you suspect something changed for good; reach for an HMM when you suspect the system is cycling between a few worlds it has visited before.

Fitting one means estimating, from data alone, each regime's mean and volatility and the transition probabilities — the classic algorithm is Baum–Welch, an instance of the EM algorithm. Two passes alternate: forward–backward turns a current guess of the parameters into a probability of being in each state on each day; the M-step turns those probabilities into a better guess of the parameters. Repeat until the fit stops improving. In production you would likely reach for statsmodels' MarkovRegression rather than hand-rolling this — but seeing the recursion once, in §5.7.7, is what makes that function something other than a black box.

💡 Tip — why the means barely matter here

Daily means are tiny next to daily volatilities, exactly as in Session 2.3 — Returns, P&L, Compounding & Leverage's arithmetic. A calm regime earning 10% a year and a crisis regime losing 15% a year differ, per day, by a few basis points — utterly swamped by volatilities several times larger. The regimes below are identified almost entirely by the change in variance, not the change in mean, which is exactly how a real crisis looks: the direction is uncertain in real time; the turbulence is not.

5.7.7 Recovering regimes, in code

Simulate a truth you know, hide it, and see how much of it an algorithm that never saw the labels can put back together.

The lab simulates 3,000 days (about 11.9 years) of a 2-state Markov chain: calm persists with probability 0.995 per day (an average run of 200 trading days), crisis with probability 0.970 (an average run of only 33 days) — so in the long run the market sits in crisis about 14.3% of the time. This one simulated run spent 19.5% of its days there — a reminder, straight out of Session 5.2 — Regression & Inference That Doesn't Lie, that one draw of even 3,000 days doesn't land exactly on a long-run average.

# forward-backward in log space (np.logaddexp is the stable log-sum-exp)
def forward_backward(log_b, log_trans, log_pi0):
    log_alpha[0] = log_pi0 + log_b[0]
    for t in range(1, T):
        log_alpha[t] = log_b[t] + np.logaddexp.reduce(
            log_alpha[t - 1][:, None] + log_trans, axis=0)

Fit from a deliberately uninformative starting guess — not the true means, variances or persistence — the EM algorithm converges in 11 iterations. A Viterbi decode of the fitted model recovers the correct regime on 98.0% of days. Table below: the recovered parameters against the truth the simulation used but the algorithm never saw.

The volatilities and persistence probabilities land close to the truth; the means, as §5.7.6 warned, are the least reliable numbers in the table — exactly because they carry the least information relative to their own noise. As in §5.7.4, one lucky fit proves nothing: refit on 25 fresh simulations and the mean recovery accuracy is 98.8%, with a standard error of only 0.18% — even four standard errors below that mean, 98.1%, is nowhere near a coin flip.

Nothing in the forward–backward recursion or the M-step above assumed exactly two states — the lab's fit_gaussian_hmm takes the number of states as an argument, and the same code fits three or five regimes just as readily. Two is the right number to start with here because two is the number the simulation actually used, which is the whole point of teaching on synthetic data: you can check the algorithm against a truth you chose yourself before ever trusting it on a market where nobody hands you the answer. On real returns, the honest next question is not "does the model fit" — a third state will always fit at least as well as two — but "does a third state earn its extra parameters", the same model-selection question Session 5.4 — Stationarity & ARMA Models asked of AR and MA lag lengths, now asked of the number of regimes instead.

None of this is only a research curiosity. A regime-probability series like fig 5.7.7's is exactly the kind of signal a risk desk uses to cut gross exposure when P(crisis)P(\text{crisis}) rises — a preview of the volatility targeting of Session 9.5 — Sizing, Vol Targeting & Allocating Across Strategies — and a pairs desk uses to decide when a hedge ratio needs rechecking rather than trusting blindly (Session 8.3 — Pairs Trading & Statistical Arbitrage). Two honest caveats before you reach for it live: the smoothed probabilities above use the whole sample, including days after the one being labelled, so a live system only ever has the noisier one-sided version; and a 2-state Gaussian model is a simplification real markets sometimes outgrow, wanting a third state or fatter-tailed emissions than Session 5.1 — Stylized Facts of Returns's Gaussian assumption allows.

5.7.9 Glossary · Check yourself · Go deeper

State-space model — a system split into a hidden state that evolves on its own and noisy observations that are all you ever see of it.
Kalman filter — the recursive predict/update recipe for tracking a continuous hidden state when the state and every noise term are linear-Gaussian.
Dynamic hedge ratio — a hedge ratio produced by a filter that updates on every new observation, instead of being re-estimated from a fixed historical window.
Hidden Markov model — a state-space model whose hidden state is one of a handful of discrete labels, with fixed probabilities of persisting or switching.
Market regime — a persistent, recurring set of statistical conditions (e.g. calm or crisis) that the market can revisit more than once.
Structural break — a permanent change in the relationship itself, after which the old parameter value never returns.

Check yourself

1. A colleague says: "the Kalman filter is basically Bayesian updating with a name recruiters recognise." Fair or not?
Fair. Treat yesterday's posterior (βˆt−1|t−1,Pt−1|t−1\hat\beta_{t-1\mid t-1}, P_{t-1\mid t-1}) as today's prior, combine it with the new observation weighted by the Kalman gain, and the result is today's posterior — the same machinery as Session 5.3's shrinkage, run once per period instead of once per dataset.
2. If the observation noise σ_ε² is much larger than the process noise q, does the filter mostly trust yesterday's estimate or today's new data point? Why?
Yesterday's estimate. The Kalman gain K_t = P x / (x²P + σ_ε²) shrinks toward zero as σ_ε² dominates the denominator, so the update barely moves — the filter is, correctly, unwilling to let one very noisy observation override a stable belief.
3. A pairs trader sets q = 0 in the code of §5.7.4. What have they actually built, and would you recommend it for a pair whose hedge ratio has broken before?
A recursive form of static (expanding-window) OLS — the sanity check earlier in the session proves the two are numerically identical. Not recommended for a pair with a history of breaks: with q = 0 the state can never move again once P has shrunk, so the "filter" can never adapt at all, however long you run it.
4. Two analysts each tune q for the same pair — one maximises pre-break likelihood only, the other maximises fit including the jump itself. Whose choice would you trust in production?
The first. The second has already seen the answer it is being asked to predict (look-ahead bias, §6.1's theme under a new name): it will pick a q that makes this one jump look perfectly ordinary, then chase noise on every future day that isn't actually a break.
5. A merger permanently doubles a stock's beta to the market; a currency's volatility spikes for two months during a crisis, then returns to its old range. Which is a structural break and which is a regime — and why does the distinction matter for choosing a tool?
The merger is a structural break: permanent, one-off, no reversion — track it with a filter (or test for it directly, e.g. Bai–Perron) rather than a model that expects the old value to come back. The volatility spike is a regime: the market revisits its old calm state, so a hidden Markov model, which explicitly allows returning to a previously-seen state, is the right tool.
6. You fit a 2-state HMM twice from different random starting guesses and get what look like contradictory results: run A calls state 1 "calm", run B calls state 1 "crisis". Is the model broken?
No — label switching. EM has no notion of which index means what; it only fits distributions to data. The fix is mechanical: sort the fitted states by a fixed criterion (here, ascending volatility) before comparing runs or reporting results, exactly as the lab does.
