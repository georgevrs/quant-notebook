6.4.1 The mental model: four places a backtest can lie

A backtest is a unit test that can pass by luck — and unlike a unit test, nobody else's code review catches it before it costs real money. Every classic way it lies enters at exactly one of four stages.

Feed a strategy the wrong history, the wrong timing, the wrong price, or the wrong audience, and it will report a Sharpe ratio that has nothing to do with reality. Those four failure points map onto the same pipeline you build in a vectorized backtest (Session 6.2 — Build a Vectorized Backtester): choose a universe, compute a signal with some timing, decide a position, get a fill — plus one stage that happens entirely outside the code: what anyone chooses to report. This session is a tour of seven classic bugs, one or two per stage, each demonstrated on a synthetic market where the true edge is known before a single line of backtest code runs — usually zero, because that is the honest baseline every trading idea has to beat. That is also why this unit sits at the centre of the course: everything from Session 6.5 — Transaction Costs & Capacity onward assumes you can already tell a genuine edge from one of these seven ghosts, and Unit 7's factor research inherits every one of them, at the scale of hundreds of published factors instead of one backtest. Practitioners have catalogued versions of this list before — Deutsche Bank's "Seven Sins of Quantitative Investing" (Luo et al., 2014, in Go deeper) is a well-known one — but grouping them by where in the pipeline they enter, rather than listing them alphabetically, makes each one easier to defend against with a specific procedural fix.

The method is the same at every stage, and it is worth naming once instead of seven times. Build a world where you, the author, know the truth. Run the version of the backtest a real researcher writes by accident — buggy, but honestly coded, not a strawman. Run the fixed version, changing exactly one thing. Compare the two numbers to the truth you built in. Nothing below is a strawman: every "buggy" version is code a competent, well-meaning researcher would actually write, because that is the only version worth learning to recognise in someone else's pull request — or your own, six months from now.

📌 Key idea — the same shape, four times

Every exhibit in this hall of fame does the same trick: it looks at an outcome that already happened and quietly lets the sample, the timing, the price or the audience be chosen by that outcome. The honest fix is always the same move, too — decide the universe, the timing, the price or the reporting rule before you know how it will turn out, exactly the discipline a pre-registered experiment enforces in any other science.

6.4.2 Universe bias: survivorship and selection

The first bug is the easiest to commit by accident: choosing which names, or which sample, you test on using information from the very outcome you are about to measure.

Session 4.2 — Point-in-Time Data & Data Biases owns survivorship bias as a data-engineering problem — most vendors' default tables only list names that still exist. Here it is live. Five thousand synthetic stocks trade for 20 years with zero true average edge: nobody in this universe has any skill, luck or story baked in, only noise. Over two decades, 40% of them random-walk down more than 80% from where they started — in a real market, most of those would have been delisted, acquired in distress or written off. Pull today's list of "constituents" and backfill each one's full history — the shortcut a vendor's "current members only" table invites — and the survivors' average total return over the period is 61.8%. Score every name that ever existed, failures included, and the honest figure is 0.16% — statistically indistinguishable from the zero edge built into the simulation. The gap is not noise; it is arithmetic. Once you throw out whichever names did worst, averaging what remains can only go up. The fix a data engineer reaches for is a point-in-time universe: store, for every past date, exactly which names existed as of that date, and query only that — 4.2's whole job.

Selection bias is the general case survivorship is one example of: building a sample using a criterion correlated with the outcome you are about to report, even when nothing failed or delisted at all. In the lab, 1,000 synthetic assets trade for 10 years, every one with zero true edge and independent noise. Rank them by their own realised Sharpe ratio and keep the top 20 — "our screen found these 20 winners" — and their in-sample average Sharpe ratio is 0.73, a figure that would read as a genuinely good systematic strategy. Re-measure the exact same 20 names on a fresh, independent draw of returns they were never selected on, and the average collapses to 0.10 — an honest, purged validation of the kind Session 6.6 — Validation: Walk-Forward, Purged K-Fold & CPCV turns into a formal procedure. The single best of the 1,000 candidates reached a Sharpe ratio of 0.99, close to the 1.03 theory predicts for the best of 1,000 skill-less trials — the False Strategy Theorem that Session 6.7 — Overfitting Statistics: PSR, DSR, MinTRL & PBO owns in full, and the same statistical fact behind the next exhibit. Notice what kind of error this is: every individual Sharpe ratio was computed correctly. The only mistake was choosing which twenty names to report using the very number being reported — a procedural failure, not an arithmetic one, and procedural failures need a procedural fix: write down the universe-selection rule (a market-cap cut-off, a liquidity screen, an economic argument for inclusion) before a single backtest result exists, and never let "the names that already look interesting" become the rule.

🧭 Margin note — one root cause

Both rows are the same mathematical move: truncate a zero-mean sample by its own outcome, and the average of what is left is no longer zero. Econometricians call the general version sample selection bias (Heckman, 1979); quants who have never opened that paper rediscover it every time they build a screen and check its own backtest.

6.4.3 Timing bias: look-ahead and data snooping

The second bug is about when you knew something — using, even in one line of code, information that would not have existed yet.

Session 4.2 — Point-in-Time Data & Data Biases owns look-ahead bias in general; its most common form inside a vectorized backtest is a missing signal lag (Session 6.2 — Build a Vectorized Backtester). Five years of a fair-game synthetic market have, by construction, zero autocorrelation, so no rule built from past returns should have any edge. Let today's own return decide the position — buy when it was up, sell when it was down — and then apply that position to the very return that produced the signal, and the "strategy" cannot lose: every day's P&L is the absolute value of that day's return, for a Sharpe ratio of 21.3. Lag the signal by one day, as the shift discipline requires, and the Sharpe ratio falls to 0.45 — consistent with zero, well inside the ordinary noise of a five-year Sharpe estimate. The tell is the buggy number itself: a Sharpe ratio above about 5 on a liquid, single-line rule is a bug report, not a discovery. In practice the bug is rarely this crude — it hides in a centred rolling window, a join against an unsorted timestamp column, or a feature built from a full-sample mean and standard deviation instead of an expanding one, each of them letting a value from the future leak a few rows sideways into the past.

Data snooping is look-ahead's sibling: instead of one accidental peek, it is many honest attempts at the same data until one happens to look good. The lab fixes one market — zero true edge, as always — and tries 3,000 independent random ±1 position rules, no real signal in any of them, over a five-year search window. The best of the 3,000 reaches a Sharpe ratio of 2.02, close to the 1.59 theory predicts for the best of that many skill-less trials (fig 6.4.3 shows the whole crowd of seeds, and how far into the tail the "winner" sits). Notice what this is: exactly the seed-hunting this course's own labs are never allowed to do, since asserting a result against a hand-picked seed is the same manoeuvre with better production values. Walk the identical rule forward onto ten fresh years it never saw, and its Sharpe ratio falls to 0.34 — indistinguishable from the zero edge that was always there. The fix is not a cleverer search; it is accounting for how many things you tried (Session 5.2 — Regression & Inference That Doesn't Lie) and pre-registering the one rule you will actually trade before you look at any result at all. Nothing about the mechanism is specific to random ±1 rules, either — the identical arithmetic applies to trying many moving-average windows, many stop-loss levels or many neural-network initialisations against one dataset. The number of trials is the hidden variable behind almost every impressively-backtested strategy, and §6.4.6 shows why counting it changes the conclusion.

⚠️ Pitfall — "I tried a few random seeds and this one backtested best"

Said about anything — a strategy, a train/test split, a neural network's initialisation — that sentence describes data snooping. The fix is not to stop trying seeds; real research tries many things. It is to fix the seed, or the specification, before looking at the result, and then to test only that one choice on data it has never touched.

6.4.4 Execution bias: stale and untradable prices

The third bug survives even a perfectly honest signal, computed at the right time, on the right names: it is the price the backtest assumes you traded at.

A single synthetic asset carries a real, small, known edge: mu=5%, sigma=20% a year, for a true Sharpe ratio of 0.25. Its quoted price, though, only partly catches up each day — the standard model of a smoothed or stale mark in an illiquid name (Getmansky, Lo & Makarov, 2004): today's observed return is 30% of today's true move plus 70% of yesterday's already-stale level. Compute a stale price Sharpe ratio on those daily observed marks — the obvious thing to do with the data you were given — and you get 0.52, more than double the true value of 0.21 (itself consistent with the 0.25 target, within the sampling noise of a ten-year estimate). The mechanism is pure arithmetic, not luck: smoothing a series keeps its mean but shrinks its measured volatility — here to 43% of the true volatility — so the same mean divided by a smaller number reports a much larger Sharpe ratio. Aggregating the same observed prices to monthly instead of daily returns, giving the staleness time to catch up, improves the estimate to 0.32: closer to the truth, though a partial cure rather than a full de-smoothing model. Real hedge-fund return series with this signature — high measured Sharpe ratios, low volatility, and returns that barely move week to week — are the same finding, at scale, and the same mechanism (Getmansky, Lo & Makarov, 2004). A practical tell is a simple regression of today's return on yesterday's: a genuinely liquid, efficiently-traded price has almost no such autocorrelation, so a suspiciously high positive one, sitting next to a suspiciously smooth equity curve, is usually staleness wearing a Sharpe ratio.

A different failure lives at the same stage: an untradable price is a printed or quoted level that no real order could ever have transacted at, for any cost — a distinct problem from the transaction costs Session 6.5 — Transaction Costs & Capacity covers in full. A thinly-traded synthetic name follows a classic breakout rule: go long when today's close crosses above the prior 20-day high, a signal built entirely from past highs, so this exhibit isolates the fill-price bug with no look-ahead mixed in. Assume every breakout fills exactly at that high, with certainty, and the 188 signals average a return of 0.42% over the following two trading weeks. But in a thin name a day's high is often a single, sizeless print with nobody real behind it (fig 6.4.4). Assume, realistically, that 40% of those prints were phantoms that no order could have touched, and that a genuine fill costs a little more than the printed level, and the average return on the trades that actually happen falls to −0.69%. A breakout rule on a random walk has no true edge either way; the honest number simply reveals it, exactly as Fama and Blume found for filter rules on the NYSE once realistic fills replaced assumed ones (1966). A practical tell here is different from the stale-price one: check whether the venue, the time of day and the size behind the assumed fill price are ones your own order could plausibly have reached. If the honest answer is "a vendor's daily summary field," assume the worst until proven otherwise.

6.4.5 Reporting bias: publication and the file drawer

The fourth bug needs no buggy code at all: every desk can be perfectly honest, and the bias still appears — in what the world gets shown.

Publication bias — sometimes called the file drawer problem (Rosenthal, 1979) — sits at the reporting stage, not the computation. Simulate 20,000 independent research desks, each honestly testing one zero-edge strategy on its own 8 years of data. Nobody here is snooping, cherry-picking or peeking; every result is a fair, independent draw with a true Sharpe ratio of exactly zero. Only the results that clear a "statistically significant" bar — here, roughly a t-statistic of 2 — ever get published, pitched to an investor, or survive to next year's performance review. Just 2.2% of desks clear that bar, but the ones that do average a Sharpe ratio of 0.84, even though the honest average across every desk, published or not, is 0.00. This is the same truncated-sample arithmetic as selection bias in §6.4.2, applied one level up the chain: not to which names enter a backtest, but to which backtests ever reach your inbox. It shows up in three familiar places: a pitch deck's "illustrative track record," a conference talk built around the one configuration that worked, and a journal that would never publish "we tested 40 factors and found nothing." Nobody in any of those rooms is lying about their own number — the lie lives in the population of attempts you never get to see.

🧭 Margin note — a cousin, not a duplicate

Publication bias is about which studies you ever get to see. A related but different problem — post-publication decay, a real edge shrinking once a factor becomes public and crowded — is Session 7.4 — The Factor Zoo & the Replication Debate's to teach in full; the two combine to make published track records look better than the future they predict, twice over.

6.4.6 The hall of fame, side by side

Put all seven exhibits next to each other and the same shape appears every time: an honest, small — often zero — true edge, and a reported number several times larger.

No single later session defends against all seven at once, which is exactly why they stay separate: transaction-cost modelling (Session 6.5 — Transaction Costs & Capacity) closes off part of the execution stage, purged validation (Session 6.6 — Validation: Walk-Forward, Purged K-Fold & CPCV) closes off part of the universe and timing stages, and the overfitting statistics of Session 6.7 — Overfitting Statistics: PSR, DSR, MinTRL & PBO put a number on how much of any remaining edge to discount for how many things were tried. ⚠️ Pitfall — "I fixed the look-ahead bug, so the backtest is trustworthy now"

Removing one bias from a seven-bias hall of fame is necessary, not sufficient. A backtest with an honest signal lag can still run on survivors only, still be the best of fifty parameter sets, and still fill at a printed high nobody could have touched. 6.4.7 Try it

Break something on purpose, then fix it — the fastest way to recognise these bugs in someone else's code.

🔧 Try it (15 min, in the lab)

Open Exhibit F (untradable price). Then set it to 0.8 and watch the honest number go further negative as fewer, worse-filled trades remain. Finally, in Exhibit E (stale price), change STALE_THETA from 0.30 to 0.05 — a much more illiquid name — and see how much further the naive Sharpe ratio inflates above the unchanged truth.

6.4.8 Glossary · Check yourself · Go deeper

Data snooping — testing many strategies, parameters or seeds against the same data until one looks good by chance.
Selection bias — building a sample using a criterion correlated with the very outcome you are about to report.
Untradable price — a printed or quoted price that no real order could actually have transacted at.
Stale price — a quoted or marked price that has not fully updated to new information, which understates measured volatility and inflates risk-adjusted returns.
Publication bias — the tendency for only the most impressive-looking results to be published, pitched or remembered, distorting the average of what anyone gets to see.

Check yourself

1. A vendor's fund database only lists funds still trading today. You backtest a strategy on its full reported history. Which direction is the bias, and why?
Upward — the average is conditioned on having survived long enough to still be listed. Exhibit A shows the mechanism directly: a survivors-only average return of 61.8% against an honest, whole-population average of 0.16%, even though every name in the lab has zero true edge.
2. You tried several random seeds for a strategy's parameters and reported the one with the best out-of-sample Sharpe ratio. Is that a valid out-of-sample result?
No — the moment you look at several seeds' results and pick the best, the "out-of-sample" set has been snooped too. Exhibit D shows the scale: the best of 3,000 skill-less seeds reached a Sharpe ratio of 2.02 in search, which fell to 0.34 the moment it met data it had genuinely never touched.
3. Two backtests of the same breakout strategy on a thin, illiquid name report very different results. One assumes every printed high fills instantly at that price; the other assumes some prints are unreachable and a real fill costs a little more. Which do you trust, and why?
The second. The first is guaranteed to overstate performance whenever a price spikes briefly through a level with no depth behind it. Exhibit F shows the same 188 signals swinging from a mean trade return of 0.42% to −0.69% once realistic fills replace assumed ones.
4. A colleague fixes the missing signal lag in their backtest and declares it "honest now." What would you check next?
Everything else on the four-stage map. Whether the universe includes delisted names, whether the strategy or its parameters were chosen by trying many and keeping the best, and whether the assumed fill price was ever really tradable. One fix removes one bias out of seven, not all of them.
5. If every research desk in the world tested strategies with zero true edge, but you only ever saw the ones that cleared a "statistically significant" bar, what would the average Sharpe ratio of everything you see look like?
Far from zero. In the lab, only 2.2% of 20,000 honest, zero-edge desks cleared the bar, and those that did averaged a Sharpe ratio of 0.84 — a completely real number describing a completely fake population average.
