1 Who this is for

Engineers who can already build things — and want to build them in markets.

The course assumes you are comfortable with Python, SQL, version control, basic statistics and the ideas behind machine learning. It assumes nothing about finance: every instrument, every convention and every piece of jargon is introduced from zero. The math is taught intuition-first; if you once passed a calculus and a linear-algebra course, you have enough to start.

3 Set up the labs

Two ways to run a lab: one click in Colab, or locally in a reproducible environment. Session 1.5 walks through the local setup in depth.

  1. Fastest: open in Colab

    Every session page has a 📓 Companion lab strip under its title. Open in Colab runs the notebook in your browser; its first cell installs the course package.

  2. Local: clone and sync

    Install uv, then clone the repository and create the environment — uv reads the lockfile, so you get exactly the versions the labs were tested with.

  3. Run a lab

    Open any labs/uNN/sSS_*.ipynb in Jupyter or VS Code, or run its .py twin from the terminal. Labs are seeded: you get the same numbers the page quotes.

$ git clone https://github.com/georgevrs/quant-notebook
$ cd quant-notebook
$ uv sync                      # core labs; add --all-extras for derivatives, ML, live trading
$ uv run python labs/u02/s03_returns_pnl_leverage.py
🧭 Margin note — why synthetic data by default

Most financial data cannot legally be redistributed, and free sources change or disappear. So labs default to seeded synthetic data generated to have the properties of real markets (fat tails, volatility clustering, factor structure). It has a second, bigger advantage: with synthetic data you know the truth, so you can test whether a method finds a real signal — and whether it "finds" one that isn't there. Labs that need real data fetch it from free sources into a local cache.

4 How to read a page

Colour means the same thing everywhere — in callouts, diagrams, badges and charts — so you learn to read it once.

CalloutWhat it holds
📌 Key ideaThe takeaway of a section — if you remember one thing, remember this.
💡 Tip / Looking aheadA shortcut, or where this idea returns later in the course.
⚠️ PitfallThe common mistake — usually the one that costs money.
🔧 Try it / Homework / LabHands-on work with a time estimate and a checkable result.
🧭 Margin noteA clarifying aside or a rule of thumb.

Formulas are real MathML rendered by your browser — no JavaScript, and they work offline. Numbers in the text that come from a lab are generated from the lab's output, so they always match what you get when you run it. Diagrams are drawn by hand; charts are drawn from lab data.

5 Errata & contributing

Finance moves and mistakes happen. If something is wrong, out of date or unclear, say so.

  • Report an erratum — session, section, what is wrong, what it should say.
  • The repository — every page, lab and tool is open source. Read CONTRIBUTING.md before a pull request.
  • Licences: text and diagrams CC BY 4.0; code (labs, quantnb, tools, and code blocks in pages) MIT. Reuse it, teach with it, credit it.
